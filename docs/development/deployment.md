# Deployment and GitHub Pages

This project publishes documentation automatically to GitHub Pages using the `gh-pages` branch.

## Workflow

File:

- `.github/workflows/docs.yml`

Behavior:

- Pull requests to `main` touching docs files run a strict docs build.
- Pushes to `main` touching docs files run build and deploy.
- Manual runs are available with `workflow_dispatch`.

## Deployment target

- Branch: `gh-pages`
- Published folder: `site/` generated by `mkdocs build --strict`

## Service deployment contract

The private Gitea workflow keeps staging and production separate. A reviewed
`develop` push deploys staging. Production is manual, runs only from canonical
`main`, and defaults to an exact immutable package; the canonical `main` commit
is available only as an explicit override. Production requires a green CI
status for the exact source, a single-use deployment authorization bound to the
exact run and requested artifacts, a verified signed completion receipt, and
unconditional cleanup of authorization material. Manual dispatches from
`develop` are rejected and do not act as staging deployments. There is no
emergency CI bypass because the signed authorization does not bind one.

## Local preview before push

```bash
uv sync --extra docs --group dev
mkdocs build --strict
mkdocs serve
```
